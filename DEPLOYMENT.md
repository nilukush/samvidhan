# Deploying Samvidhan to Cloudflare Pages

This guide covers the one-time setup and the ongoing monthly update ritual.

## One-time setup

1. Go to [Cloudflare Pages](https://pages.cloudflare.com) and sign in with a free account.
2. Click "Create a project" then "Connect to Git".
3. Select the `nilukush/samvidhan` repository from GitHub.
4. Configure the build:
   - Framework preset: None
   - Build command: `npm run build`
   - Build output directory: `dist`
   - Root directory: `/`
5. Click "Save and Deploy". The first build takes about 5 minutes (model fetch, embedding, pagefind).
6. Your site is live at `samvidhan.pages.dev` (or whatever name Cloudflare assigns).

## Verifying the deployment

After the first deploy, run the smoke tests:

```bash
./scripts/smoke-test.sh https://samvidhan.pages.dev
```

All 29 checks should pass. The script verifies:
- Home page, article pages, amendment pages, bills tracker all serve content
- JSON-LD structured data on article pages
- The sitemap lists articles and amendments
- robots.txt and llms.txt are reachable
- The search controller, Pagefind bundle, and concept module are served
- The essentials page serves with the 106th Amendment caveat
- Unknown paths return a 404 page instead of the homepage

## Search engine submission (one-time, free)

The sitemap is already live and regenerated by every build (`@astrojs/sitemap` in `astro.config.ts`, announced in `robots.txt`). What remains is telling the search engines about the site:

1. Google Search Console: add a URL-prefix property for `https://samvidhan.pages.dev/` and verify with the HTML file method. The verification file lives at `public/googled3cc5e1274fa98d4.html` and deploys to the site root. Then submit `sitemap-index.xml` in the Sitemaps report.
2. Bing Webmaster Tools: use "Import from Google Search Console" after step 1, or verify with a `BingSiteAuth.xml` file committed to `public/` the same way.
3. The sitemap intentionally carries no `lastmod`. Build timestamps would be inaccurate and search engines ignore them. Only add `lastmod` if it derives from real per-page content change dates.

Renaming the Cloudflare Pages project invalidates the Search Console property: `SITE_URL` (`src/config.ts`), `robots.txt`, and `llms.txt` all hardcode `samvidhan.pages.dev`.

## Ongoing cost

Zero. Cloudflare Pages free tier includes:
- Unlimited bandwidth and static requests
- 500 builds per month
- Unlimited sites

The only optional cost is a custom domain (about 10 dollars per year). The free `pages.dev` subdomain works fine.

## Portability

The site is a plain static bundle in `dist/`. If Cloudflare changes its free tier terms, the same output deploys unchanged to GitHub Pages, Netlify, or any static file host.

## The monthly update ritual

See [CONTRIBUTING.md](CONTRIBUTING.md) for the full ritual. The short version:

1. Check legislative.gov.in for a new Constitution edition PDF
2. Check Wikipedia's amendment list for new enactments
3. Check sansad.in and prsindia.org for bill status changes
4. Update `data/source/` (new PDF), rerun `npm run data:extract && npm run data:amendments && npm run data:embed`
5. Update `src/data/bills/snapshot.json` with fresh `lastVerified` dates
6. Push to GitHub. Cloudflare rebuilds and deploys automatically.
7. Run `./scripts/smoke-test.sh https://samvidhan.pages.dev` to confirm.

## Architecture notes

- No Cloudflare Workers, no bindings, no compute in the request path
- Static assets only, so the billing surface is zero
- The build chain: `data:sync` then `vendor:ai` then `astro build` then `pagefind --site dist`
- The concept search model (~45 MB total including WASM runtime) is vendored into `public/vendor/` and `public/models/` at build time; it is gitignored and regenerated in CI
- The vector index (`public/vectors/chunks.json`, 1.4 MB) is regenerated by `npm run data:embed`
- All three generated directories (`vendor/`, `models/`, `vectors/`) are gitignored and rebuilt on every CI run and Cloudflare Pages deploy
